## Notes for whoever picks this up next

Confirmed on dev (2026-10-15):

- Each Overview card (Customer Profile, System, Customer Management, Departments and Assignees) is its own `<section>` with an `<h2>`. Profile, Management and Departments each have an "Edit" button that swaps to "Cancel"/"Save" and turns only that card's fields into inputs/comboboxes.
- While one section is in edit mode, the other sections are read-only but their own "Edit" buttons stay **enabled** — clicking Management's Edit while Profile is open opens both at once. TC:2 only asks that the other sections stay read-only (they do), so this is noted, not flagged as a bug.
- Successful save → toast "Customer Profile updated", card back to read-only, Profile → Version increments, System → Updated On refreshes.
- Customer Name is the only mandatory Profile field (" •" marker). Blank Customer Name → inline "Required" + `aria-invalid="true"`, section stays in edit mode, nothing persisted. Email is _not_ mandatory on this screen — saving it blank succeeds.
- Locked fields: Version (Profile), Status (Management) and all System fields (Customer Code, Created On/By, Updated On/By) show a padlock (`title="Locked field"`) and never get an input.
- TC:4: the screen's tabs are Overview, Lead Qualification, Biz Docs, Communication, Contacts — none has an Audit History. Kept as `test.fixme()` with the intended steps so it can be enabled when the feature ships.
