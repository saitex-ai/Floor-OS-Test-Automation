# Planning — Recipes (List / Create / Edit)

- **User Story:** As a Planner, I want to define how a piece of work is performed — a recipe, owned by a department, filling an activity — so its duration comes from its operations.
- **Test-case set:** [ClickUp — Planning -Sprint -1 - Recipes & Operations](https://app.clickup.com/t/z941abu5e6) (one subtask per TC, in "Test Cases and Runs").
- **Automated in:** [`tests/regression/planning/05-recipes.spec.ts`](../../tests/regression/planning/05-recipes.spec.ts) — 35 cases.
- **Page objects:** [`recipes-list.page.ts`](../../src/pages/planning/recipes-list.page.ts), [`recipe-form.page.ts`](../../src/pages/planning/recipe-form.page.ts), [`recipe-detail.page.ts`](../../src/pages/planning/recipe-detail.page.ts), [`operation-form.page.ts`](../../src/pages/planning/operation-form.page.ts)
- **Latest run:** dev, 2026-10-30, as `alice` (Admin); permission cases as carol (read-only) and dave (no access); 2 workers — 35 pass.

Since Sprint 1 recipes are **versioned drafts**: "Create recipe" makes draft v1 ("Recipe created as a draft. Send it for approval when it is ready."), only a draft can be edited, and the list shows one row per version. Only Code and Recipe block saving; the rest are listed as "Before it can be sent for approval, fill in: …". The suite never sends anything for approval.

**Test data:** every record this suite creates carries "QA-AUTO — Planning regression test data (pw-hybrid-framework). Safe to delete." (in its name, or a grade's Description), so it can be found and deleted from the backend. The suite never edits seed records. When a spec file finishes, its `afterAll` deletes the activity and recipe drafts it created and retires its difficulty grades (grades can't be deleted) — see `tests/regression/planning/support/cleanup.ts` and `test-data.ts`. Since the 2026-10-16 dev deploy, dev generates activity, recipe, operation, work-centre and machine codes (ACT-0001…, RCP-0001…, OP-0001…, WC-0001…, MC-0001…): each such record carries a run-unique tag in its name (a machine: in its QA-AUTO system link), the suite reads the generated code back after saving, and cleanup finds the record by that tag. Difficulty-grade codes are still typed (`QG<run><n>`).
