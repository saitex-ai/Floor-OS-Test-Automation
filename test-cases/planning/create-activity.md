# Planning — Create Activity

- **User Story:** As a Planner, I want to define a new Activity — the smallest named kind of work the factory performs — so the plan can schedule it.
- **Test-case set:** [ClickUp — Planning -Sprint -1 - Activities](https://app.clickup.com/t/z941abtdu1) (one subtask per TC, in "Test Cases and Runs").
- **Automated in:** [`tests/regression/planning/02-create-activity.spec.ts`](../../tests/regression/planning/02-create-activity.spec.ts) — 13 cases.
- **Page objects:** [`activities-list.page.ts`](../../src/pages/planning/activities-list.page.ts), [`activity-form.page.ts`](../../src/pages/planning/activity-form.page.ts), shared grid [`master-data-list.page.ts`](../../src/pages/planning/master-data-list.page.ts) (fixtures `activitiesListPage`, `activityFormPage`)
- **Latest run:** dev, 2026-10-30, as `alice` (Admin); permission cases as carol (read-only) and dave (no access); 2 workers — 12 pass, 1 skip.

Since Sprint 1, **"New activity" creates a draft** ("Creates a draft. Send it for approval from its page to publish it."). Only Activity code and Activity name block saving; the other required fields are listed on the draft's page as "Before it can be sent for approval, fill in: …". The suite never sends anything for approval. Cases that asserted Sprint 1 behaviour the app has deliberately changed say so in the last column.

**Test data:** every record this suite creates carries "QA-AUTO — Planning regression test data (pw-hybrid-framework). Safe to delete." (in its name, or a grade's Description), so it can be found and deleted from the backend. The suite never edits seed records. When a spec file finishes, its `afterAll` deletes the activity and recipe drafts it created and retires its difficulty grades (grades can't be deleted) — see `tests/regression/planning/support/cleanup.ts` and `test-data.ts`. Since the 2026-10-16 dev deploy, dev generates activity, recipe, operation, work-centre and machine codes (ACT-0001…, RCP-0001…, OP-0001…, WC-0001…, MC-0001…): each such record carries a run-unique tag in its name (a machine: in its QA-AUTO system link), the suite reads the generated code back after saving, and cleanup finds the record by that tag. Difficulty-grade codes are still typed (`QG<run><n>`).

## Notes for whoever picks this up next

- Live labels differ from the ClickUp wording: Unit of work = "Duration scales by", Time basis = "Time applies", Capture method = "Actuals captured by", Completion event = "Closed by".
- Every select is a combobox (click, then the option); "Owning department" and "Must follow activity" are searchable.
- Number fields filter keystrokes: "-" and letters never land, so "rejected" means the value can't be entered.
- Activity codes are generated on save since the 2026-10-16 dev deploy (ACT-0001…, not department-prefixed any more); the suite tags each draft's name with `CUT-QA<run><n>` and reads the code back from the list.
