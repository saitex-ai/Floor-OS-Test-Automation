- **User Story:** [Shift](https://app.clickup.com/t/90181912927/86eypv70q)

- **Page objects:** [`shifts.page.ts`](../../src/pages/planning/shifts.page.ts), [`date-picker.ts`](../../src/pages/planning/date-picker.ts).
- **Latest run:** dev, 2026-10-30, as `alice` (Admin); permission cases as carol (read-only) and dave (no access); 2 workers — 49 pass, 1 known bug.

Shifts & breaks (`/planning/master-data/shifts`) create and edit shifts on their own pages. Breaks belong to the shift. Since the 2026-10-28 dev deploy the create and edit forms are two steps (step 1's "Save & continue" saves, Done opens the detail page), and breaks are rows of an inline table on step 2 of Edit shift: the add row ("Add break"; its ✕ Clear discards what was typed), and a saved row's "Edit break" with Save / Cancel on the row. Each row saves on its own. The detail page shows the table read-only, and Done / Cancel refuse to leave while the add row holds input. A new break is always Active; it is retired by editing its row. Gross minutes and a break's length are derived, never typed.

**Test data:** every record this suite creates carries "QA-AUTO" in its name, label or description, so it can be found and deleted from the backend. The suite never edits seed records. When a spec file finishes, its `afterAll` retires what it created (these masters can't be deleted) — see `tests/regression/planning/support/cleanup.ts` and `test-data.ts`. Shift codes are generated on save (SH-0001…, since 2026-10-16); each QA shift's name carries a run-unique `QA_SH…` tag. The suite builds a day shift (07:30 → 16:30, unpaid Lunch and paid Tea), a night shift (22:00 → 06:00, Tea after midnight) and a bare 08:00 → 12:00 shift.

## Notes for whoever picks this up next

- Lists are the shared Master Data grid (`MasterDataListPage`): `expectLoaded()` waits past the skeleton rows; search / filters apply after a debounce, so assert with `expect.poll` / `expectEveryRowMatches()`. Header text carries the sort arrows (↑ ⇅) — strip them before comparing.
- Permission cases run as the optional `PLANNING_READONLY_*` / `PLANNING_NOACCESS_*` logins (see `.env.example`), each logged in once per worker (`personas` fixture), and skip without them. Where a read-only user is still offered an enabled control, the case drives it and checks the write is refused.
- Success toasts fade after a few seconds: `submitExpectingToast()` checks them straight after the click. An open modal hides the grid behind it from the accessibility tree, so read a row before opening its dialog.
- Start / end are time pickers: hour buttons, then minute buttons, in one "Pick time" group; a set trigger reads "07:30 AM". `pickTime()` presses Escape if the popover stays open.
- With "Crosses midnight" off, 22:00 → 06:00 reads a negative gross and Create is blocked.
- A set time trigger's accessible name is "07:30 AM Clear time" (the clear button nests inside it).
- Check break cells one by one: the row's text runs them together ("12:3030").
