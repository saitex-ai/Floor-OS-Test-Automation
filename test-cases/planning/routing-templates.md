- **Latest run:** RESULTS_PLACEHOLDER

Routing templates (`/planning/master-data/routing-templates`) are the ordered skeleton of steps one cycle kind runs, for one product type × wash type (or any product). "New template" opens `/routing-templates/new`: a never-saved draft with an inline header (Cycle kind, Product type, Wash type, Template code — generated on save, Template name, Description) and an empty steps table. Save draft stores it (`RT-0001…`) and moves to `/routing-templates/<uuid>`; its header is then edited in the "Edit routing template" dialog. Validate checks the steps; Publish (enabled once validated) makes revision 1 live. An Active template is read-only until "Edit template" starts a pending revision (Live / Pending tabs, "Changes vs revision N", Cancel revision). Retire and Duplicate are list row actions.

**Test data:** every template this suite creates is named `QA-AUTO <tag> — routing-templates test data (pw-hybrid-framework). Safe to delete.`, so it can be found and deleted from the backend. The suite never edits seeded templates (it only reads one AI-proposed template). Templates can't be deleted: the spec's `afterAll` retires its Active ones (cancelling a pending revision first); its Drafts stay, tagged. Templates are only published on a cycle kind × product type × wash type that no live template uses (see the notes).

## Notes for whoever picks this up next

- **One live template per cycle kind × product type × wash type.** Publishing a template retires the Active one on the same triple and names the new one as its successor (the Publish dialog says so: "<code> is the active template for this cycle kind, product type and wash type. Publishing retires it…"). So the suite only publishes on a triple no live template uses (`freeTriple()`, read from the list's own `limit=200` request) and `publish()` cancels and fails rather than confirm a dialog that would retire anything. Never publish on a seeded template's triple.
- **uat (2026-11-17):** the screen loads but has no templates, no product or wash types, cycle kinds without labels, and the activity picker lists nothing ("No activity matches."), so no step — and no saved template — can be built. Only the cases that need no step run there; the rest skip with `NO_CATALOGUE`.
- **Approval flow:** dev confirmed direct Publish is the interim; Submit for approval / department sign-off ship later. The approval cases skip while "Submit for approval" / "Pending approval" isn't on the page and fail (on purpose) once it is — re-test them then. Parts of other cases that need the flow are recorded as "not covered" annotations.
- **Radix on this screen:** the "Step N actions" menus need a real `.click()` (`dispatchEvent` silently does nothing); the "Choose activity…" trigger needs `dispatchEvent` (a real click can retry forever under the picker's overlay). Recipe binding, Start after and Lag counts are tabs. The first click on "Edit template" right after the page renders is sometimes dropped — `startRevision()` retries until "Cancel revision" shows.
- A refused Save draft opens the issue list at the bottom left, which covers "Add step": `dismissIssues()` closes it first.
- Steps are picked from the picker's own catalogue (`readCatalogue()`: one activity from each of three departments, other suites' QA-AUTO activities skipped), so nothing depends on a seeded activity code.
- Cleanup: templates can't be deleted. `afterAll` retires this file's Active templates (cancelling a pending revision first); Drafts stay, tagged "QA-AUTO … Safe to delete".
