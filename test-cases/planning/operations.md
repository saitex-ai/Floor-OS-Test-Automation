# Planning — Operations (Create / Edit / List)

- **User Story:** As a Planner, I want to keep the Operation Master — every operation the floor performs, with its department, difficulty grade, machine type, skill grade and standard times — so bulletins and recipes can use them.
- **Test-case set:** [ClickUp — Planning -Sprint -2 - Operations and Allowance](https://app.clickup.com/t/z941abv8mt) (one subtask per TC, in "Test Cases and Runs").
- **Automated in:** [`tests/regression/planning/07-operations.spec.ts`](../../tests/regression/planning/07-operations.spec.ts) — 26 cases.
- **Page objects:** [`operations-list.page.ts`](../../src/pages/planning/operations-list.page.ts), [`operation-master-form.page.ts`](../../src/pages/planning/operation-master-form.page.ts), [`operation-detail.page.ts`](../../src/pages/planning/operation-detail.page.ts), shared grid [`master-data-list.page.ts`](../../src/pages/planning/master-data-list.page.ts) (fixtures `operationsListPage`, `operationMasterFormPage`, `operationDetailPage`)
- **Latest run:** dev, 2026-10-14 (after that day's deploy), as `alice` (Admin); permission cases as carol (read-only) and dave (no access); 2 workers — 23 pass, 3 skip.

The screen is "Operation Master" at `/planning/master-data/operations`; a detail page's URL carries the code (`/operations/<CODE>`). New operations start as Draft, but the form still needs Owning department and Difficulty grade (and Machine type for an on-machine grade). The suite uses the off-machine grade "M — manual" so Machine type can stay empty.

**Test data:** every record this suite creates carries "QA-AUTO" — in its name (operations, work centres), a "QA-AUTO" system link under Asset register & telemetry (machines have no name), or its Why (maintenance windows) — so it can be found and deleted from the backend. The suite never edits seed records. When a spec file finishes, its `afterAll` retires the operations, work centres and machines it created (they can't be deleted) — see `tests/regression/planning/support/cleanup.ts` and `test-data.ts`.

## Notes for whoever picks this up next

- Lists are the shared Master Data grid (`MasterDataListPage`): `expectLoaded()` waits past the skeleton rows; search / filters apply after a debounce, so assert with `expect.poll` / `expectEveryRowMatches()`.
- Permission cases run as the optional `PLANNING_READONLY_*` / `PLANNING_NOACCESS_*` logins (see `.env.example`), each logged in once per worker (`personas` fixture), and skip without them. Where a read-only user is still offered an enabled control (ClickUp z941abybge), the case drives it and checks the write is refused.
- A blocked save shows "Fill the N highlighted field(s) before saving." for a few seconds only: `submitExpectingBlocked()` checks it straight after the click.
- "Last studied on" is a date picker ("Pick date" → today); its label reads "Last studied on *" while the switch is on.
- Operations can't be deleted, only retired.
- Seed data: the Sewing department, the off-machine difficulty grade (`M — manual`), skill grades S2 / S3, and the seed operation "5-thread safety overlock" (TC-LO-02's search).
