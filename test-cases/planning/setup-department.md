- **User Story:** [Set up my Department Wizard](https://app.clickup.com/t/90181912927/86eypv7u6)
- **Test-case set:** [ClickUp — Planning -Sprint -3 - Set up my Department Wizard](https://app.clickup.com/t/z941abw0ny) (one subtask per TC, in "Test Cases and Runs").
- **Automated in:** [`tests/regression/planning/18-setup-department.spec.ts`](../../tests/regression/planning/18-setup-department.spec.ts) — 45 cases.
- **Page objects:** [`setup-department.page.ts`](../../src/pages/planning/setup-department.page.ts), [`departments-list.page.ts`](../../src/pages/master-data/departments-list.page.ts), [`department-form.page.ts`](../../src/pages/master-data/department-form.page.ts).
- **Latest run:** dev, 2026-10-16, as `alice` (Admin); permission cases as carol (read-only) and dave (no access) — 38 pass, 7 skip.

A 7-step guided journey (`/planning/master-data/setup-department`), started from the "Set up my department" card on the Master Data landing page. The rail opens steps up to the furthest one reached, and progress % follows that. Every step's add / edit is the standalone screen's own form, inline and scoped to the department being set up — and every save is live master data at once.

**Test data:** every record this suite creates carries "QA-AUTO" in its name, label or description, so it can be found and deleted from the backend. The suite never edits seed records. When a spec file finishes, its `afterAll` retires what it created (these masters can't be deleted) — see `tests/regression/planning/support/cleanup.ts` and `test-data.ts`. The wizard writes real master data, so the cases run serially on a QA department this file creates in Step 1 (`QAD…`, Active, Internal, FACTORY-2627, Line) with `<dept>-A1`, `-R1`, `-WC1`, `-M1` and "QA-AUTO <dept> operator". `afterAll` deletes the activity and recipe drafts, retires the centre and machine, and deactivates the employee and the department. Real departments are only read.

## Notes for whoever picks this up next

- Lists are the shared Master Data grid (`MasterDataListPage`): `expectLoaded()` waits past the skeleton rows; search / filters apply after a debounce, so assert with `expect.poll` / `expectEveryRowMatches()`. Header text carries the sort arrows (↑ ⇅) — strip them before comparing.
- Permission cases run as the optional `PLANNING_READONLY_*` / `PLANNING_NOACCESS_*` logins (see `.env.example`), each logged in once per worker (`personas` fixture), and skip without them. Where a read-only user is still offered an enabled control, the case drives it and checks the write is refused.
- Success toasts fade after a few seconds: `submitExpectingToast()` checks them straight after the click. An open modal hides the grid behind it from the accessibility tree, so read a row before opening its dialog.
- A new department's Active switch starts off, and an inactive department can't own activities ("departmentCode … is retired"), so `createDepartment()` turns it on.
- Step 5 (Capacity) still reads "This step is not built yet": its cases skip until it is, and Review's Capacity line is a placeholder.
- Dev 2026-10-14: a department created in Step 1 reaches Planning a few seconds later. The inline forms read the department when they open — opened sooner, the locked department reads "Select…" and Create is refused ("Unknown departmentCode"), and an open form never updates. `openCreateActivityOnceKnown()` reopens the form; `reopen()` reloads the wizard.
- The inline employee form's name field is "Name" (Master Data says "Full Name"), and its submit is exactly "Create employee" — the step's own button reads "+ Create employee".
- Department edits happen in place on Step 1 (no heading): the code locks and "Saves in place" shows.
- Since the 2026-10-14 deploy, Step 4's machine form has a Machine type picker (no Machine class); the QA machine is "BTK · Bartack" with its QA-AUTO marker in a system link, as on the Machines screen. The qualification TC-DW-TEAM-04 adds stays on the (deactivated) QA-AUTO employee: with no operator profile there's nowhere to retire it.
- Seed data relied on: CUT (confirmed, with CUT- activities) for TC-DW-DEPT-01/02, the FACTORY-2627 calendar for new departments, and task SEW-COINHEM for TC-DW-TEAM-04.
