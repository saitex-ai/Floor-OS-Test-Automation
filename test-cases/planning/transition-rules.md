Transition rules (`/planning/master-data/transition-rules`) say what a change costs a work centre: minutes of changeover at the boundary and a learning-curve ramp afterwards. A plain master (no versions or approval), Sewing lines only in v1. The list has change-class summary cards, All / Active / Inactive tabs and the shared grid (search, Filters, columns, split views); a row opens a read-only view page (`/transition-rules/<id>`), and Edit opens the editor. Since dev's 2026-10-28 redesign the editor (`/new`, `/<id>/edit`) has two steps — Rule details (name, generated code, Applies to, priority, Active, description, change class) and Conditions and ramp (Applies when, Changeover, Learning curve, Evidence, Ramp panel). Continue saves nothing; Create / Save writes the whole rule. The footer names the first thing blocking a save ("Can't save yet · <reason> (+N more)"). Rules are never deleted, only deactivated.

**Test data:** every rule this suite creates is its own: its name carries a run-unique `QATR…` tag plus "QA-AUTO — transition-rules test data (pw-hybrid-framework). Safe to delete.", and its Description carries the same marker. The seeded `SEW-*` rules exist on dev only and are never read or changed. When the spec finishes, its `afterAll` deactivates every rule it created that is still active (`cleanUpRulesAfterAll()` in `support/transition-rules.ts`).

## Notes for whoever picks this up next

- **Bugs:** the nine bugs this screen had (z941aby4bu, z941aby4by, z941aby4c1–z941aby4c7) are all Closed in ClickUp, so no case carries `knownBug()`. The cases that used to fail on them (CTR-02, CTR-13, CTR-15, CTR-17, CTR-22, ETR-05, ETR-07, ETR-10, ETR-11, LTR-03, LTR-08, LTR-09) now assert the fixed behaviour.
- **Generated code:** the code is `TR-0001…`, generated on save and locked ever after. CTR-03 / CTR-04 / ETR-05 were written for a typed, renameable code; they are re-titled to check what replaced it, and (with LTR-10, which checks there is no Duplicate) are listed for PO sign-off on the ClickUp TCs.
- **Rows have no code cell:** the Rule cell reads "<name> <subtitle> · <CODE>[· ambiguous]", so rows are found by that suffix (`TransitionRulesListLocators.row()`). A row's text runs its cells together ("· TR-0037Similar…"), which is why the suffix only refuses a following digit.
- **Search is server-side** (`GET /api/planning/transition-rules?search=`). `TransitionRulesListPage.search()` waits for that response and then for the grid to show exactly the codes it returned — a description match isn't visible in the row. While it fetches, the grid can briefly show the old rows, no rows or the no-match state; a search the page already ran can come from the cache with no request at all.
- **Tab counts and the Active tab** read 0 for a moment while a tab refetches: poll them, never read them once.
- **Split view is remembered** between visits; `TransitionRulesListPage.open()` always puts the list back in List view.
- **The Day by day table's boxes** refresh a moment after a row is removed (for a beat they still show the old values): use `expectTableValues()`.
- **Toasts** (2026-11-17): "Curve refitted from N measured points — Save to keep it" has no closing full stop, and a Day by day refit gives the same toast, without the case's "— the day-by-day table was rewritten." (the dialog still says the table is rewritten, and the table is). Copy only.
- **"Last refitted"** reads "Last refitted by You · <date>" in the editor until the save, then the user's name (`refitByName` from the save).
- **The no-access persona** never gets the app's user menu on dev — it sits on "Loading Planning…" at `/` — so `expectNoAccess()` uses a plain `goto()`, not `gotoAuthenticated()`.
- **The zero-rule state** is only on an environment before its first rule (uat on 2026-11-17 had none until this suite ran), so TC-LTR-12 serves the page an empty list read.
- **Skips:** TC-CTR-23 skips when the environment has no QA-AUTO/Playwright sewing-line centre (it never uses a real centre); TC-ETR-06 skips when the activity picker offers only "None"; TC-ETR-19 and TC-LTR-01 skip without their persona login.
- **Persona cases:** TC-ETR-19 (READONLY persona) and the no-access half of TC-LTR-01 (NOACCESS persona) need those logins in `.env`; the read-only persona has `planning.transition-rule.read` on dev and uat.
