# Planning — Difficulty Grade

- **User Story:** As a Planner, I want to define how demanding an operation is (Master Data > Difficulty grades) — the factor applied last, after allowances — so recipe operations can be graded consistently.
- **Test-case set:** [ClickUp — Planning -Sprint -1 - Difficulty Grade](https://app.clickup.com/t/z941abu3rk) (one subtask per TC, in "Test Cases and Runs").
- **Automated in:** [`tests/regression/planning/04-difficulty-grade.spec.ts`](../../tests/regression/planning/04-difficulty-grade.spec.ts) — 36 cases.
- **Page objects:** [`difficulty-grade-list.page.ts`](../../src/pages/planning/difficulty-grade-list.page.ts), [`difficulty-grade-form.page.ts`](../../src/pages/planning/difficulty-grade-form.page.ts); for the dropdown cases [`recipe-detail.page.ts`](../../src/pages/planning/recipe-detail.page.ts) + [`operation-form.page.ts`](../../src/pages/planning/operation-form.page.ts)
- **Latest run:** dev, 2026-10-30, as `alice` (Admin); permission cases as carol (read-only) and dave (no access); 2 workers — 36 pass.

On 2026-10-09 dev had 6 grades of its own (A, BM, B, C, D, M) — read, never edited; the 23 QA grades from Sept were gone. Grades can't be deleted, only retired. The dropdown-order and "in use" cases rate one operation on a QA-AUTO recipe with a QA grade (built in `beforeAll`).

**Test data:** every record this suite creates carries "QA-AUTO — Planning regression test data (pw-hybrid-framework). Safe to delete." (in its name, or a grade's Description), so it can be found and deleted from the backend. The suite never edits seed records. When a spec file finishes, its `afterAll` deletes the activity and recipe drafts it created and retires its difficulty grades (grades can't be deleted) — see `tests/regression/planning/support/cleanup.ts` and `test-data.ts`. Since the 2026-10-16 dev deploy, dev generates activity, recipe, operation, work-centre and machine codes (ACT-0001…, RCP-0001…, OP-0001…, WC-0001…, MC-0001…): each such record carries a run-unique tag in its name (a machine: in its QA-AUTO system link), the suite reads the generated code back after saving, and cleanup finds the record by that tag. Difficulty-grade codes are still typed (`QG<run><n>`).

## Notes for whoever picks this up next

- Grade codes keep the case they were typed in (seed "bm") but display upper case; the suite only uses upper-case codes.
- The operation's Difficulty grade options are the grades' labels, in Sort order; retired grades are left out.
- The permission cases (TC-CG-10, TC-EG-11, TC-LG-11) need the optional `PLANNING_READONLY_*` / `PLANNING_NOACCESS_*` logins (see `.env.example`); they skip without them.
