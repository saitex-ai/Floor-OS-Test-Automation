# Planning — Work Centres (Create / Edit / List)

- **User Story:** As a Planner, I want to define work centres — where work runs, what capacity they have and which activities they can run — so orders land only where they can be done.
- **Test-case set:** [ClickUp — Planning -Sprint-2 - Work Centre](https://app.clickup.com/t/z941abvb7u) (one subtask per TC, in "Test Cases and Runs").
- **Automated in:** [`tests/regression/planning/09-work-centres.spec.ts`](../../tests/regression/planning/09-work-centres.spec.ts) — 24 cases.
- **Page objects:** [`work-centres-list.page.ts`](../../src/pages/planning/work-centres-list.page.ts), [`work-centre-form.page.ts`](../../src/pages/planning/work-centre-form.page.ts), [`work-centre-detail.page.ts`](../../src/pages/planning/work-centre-detail.page.ts), shared grid [`master-data-list.page.ts`](../../src/pages/planning/master-data-list.page.ts) (fixtures `workCentresListPage`, `workCentreFormPage`, `workCentreDetailPage`)
- **Latest run:** dev, 2026-10-12, as `alice` (Admin); permission cases as carol (read-only) and dave (no access) — 24 pass.

Work centres are at `/planning/master-data/work-centres`; detail and edit pages use the record's uuid. A create returns to the list ("Work centre created."); Save changes returns to the detail page ("Work centre updated."). Version / Effective from / Effective to removed on request — [Demo Feedback](https://app.clickup.com/t/90181912927/z941abwdad) (implemented 2026-09-25).

**Test data:** every record this suite creates carries "QA-AUTO" — in its name (operations, work centres), its Machine class (machines have no name), or its Why (maintenance windows) — so it can be found and deleted from the backend. The suite never edits seed records. When a spec file finishes, its `afterAll` retires the operations, work centres and machines it created (they can't be deleted) — see `tests/regression/planning/support/cleanup.ts` and `test-data.ts`.

## Notes for whoever picks this up next

- Lists are the shared Master Data grid (`MasterDataListPage`): `expectLoaded()` waits past the skeleton rows; search / filters apply after a debounce, so assert with `expect.poll` / `expectEveryRowMatches()`.
- Permission cases run as the optional `PLANNING_READONLY_*` / `PLANNING_NOACCESS_*` logins (see `.env.example`), each logged in once per worker (`personas` fixture), and skip without them. Where a read-only user is still offered an enabled control (ClickUp z941abybge), the case drives it and checks the write is refused.
- The list tabs are the capacity pools ("What it is used for"); a tab only appears once a centre uses that pool. Tab counts are re-read together until they agree (`expectTabCountsAddUp()`), since another worker can create or retire centres mid-read.
- Seed data: the `SEW-MAIN` activity (capability rows) and the Sewing / Cutting departments. TC-EWC-02 picks any working calendar other than the current one, so it doesn't depend on a year-bound seed calendar like "Factory 2026-27".
- The smoke test still uses `fillRequired()` / `create()` / `expectCreatedSuccessfully()`; the regression suite uses `submitCreate()`.
