# Planning — Operators & Qualifications (List / Create / View / Edit)

- **User Story:** [Operator Profile and Qualification - Additional changes](https://app.clickup.com/t/90181912927/z941aby6j3) — one screen for an operator's profile (home centre, usual shift, grade, deployment) and the tasks / activities they're qualified on. It replaces the separate Operator Profiles (story z941abtcrv) and Qualifications screens.
- **Test-case set:** [ClickUp — Planning - Operators & Qualifications](https://app.clickup.com/t/z941abzdqq) (one subtask per TC, in "Test Cases and Runs"). 88 cases; TC-LOQ-17, TC-XOQ-04, TC-XOQ-08 and TC-XOQ-11 were removed on review. The older "Planning -Sprint -4 - Operator Profiles" set (z941abxn2e, TC-COP/EOP/LOP) is superseded by this one.
- **Automated in:** [`tests/regression/planning/19-operators-qualifications.spec.ts`](../../tests/regression/planning/19-operators-qualifications.spec.ts) — 88 cases.
- **Page objects:** [`operators-list.page.ts`](../../src/pages/planning/operators-list.page.ts), [`operator-profile.page.ts`](../../src/pages/planning/operator-profile.page.ts) (view, the stepped New / Edit form and the qualifications table); support in [`support/operators.ts`](../../tests/regression/planning/support/operators.ts).
- **Latest run:** RESULTS_PLACEHOLDER

Routes: list `/planning/master-data/operators`, New `/new`, view `/{id}`, Edit `/{id}/edit`. The old `/planning/master-data/qualifications` renders "Not Found".

**Test data:** an operator profile hangs off an employee (at most one profile per employee; profiles are retired, never deleted), so every operator the suite uses gets its own employee, created in Master Data › Employees in Sewing and named "QA-AUTO OQ<run> — operator-profiles test data (pw-hybrid-framework). Safe to delete." Real employees and seed profiles are only read; TC-XOQ-10 changes the department of one of the suite's own employees. Each worker first builds a "rich" operator (LINE-30, S2, efficiency 95, 11 task qualifications — one IE-assessed, one lapsed, one not qualified, one retired, one valid until next month, six plain — plus one activity where activities exist) and a "blank" one (Floating, nothing else set). When the file finishes, its `afterAll` retires every operator it created and switches its employees off.

## Notes for whoever picks this up next

- **The form is stepped** (since the 2026-10-28 deploy, after these cases were written): step 1 is the profile, and "Save & continue" creates or saves it; step 2 is the qualifications table, where each row saves on its own (POST / PUT `/api/planning/qualifications`); Done opens the view. So the create-with-qualifications cases (TC-COQ-06..11) add their rows on step 2 of a new operator, a "staged" row is now the add row before it's added (Clear takes it off), and the profile's old "Save changes" is step 2's Done (TC-EQQ-16).
- **Clicking the "Qualifications" step on Edit saves pending step-1 changes** (dev and uat, 2026-11-17). Cancel, or the back link, asks "Leave without saving?" (Keep editing / Discard and leave).
- **A retired qualification is listed but not counted** (since z941abzdat was fixed): "Qualifications (N)", Certifications and Qualified count the active rows; the retired row reads Active "No" and "Not qualified".
- **A new employee reaches the New operator Employee picker a few seconds late** (dev 2026-11-17). `pickEmployee()` reloads the form until it's offered.
- **Rows have no spaces between their parts:** a list row reads "EMP-000396QA-AUTO…", a qualification row "SEW-COINHEMCoin pocket hem". `operatorRow()` and `qualificationRow()` match the code element, not a word in the row's text.
- **Wait for the qualifications to load:** the table starts as "Qualifications (0)" with the empty message and fills when GET `/api/planning/qualifications` answers; the add row's pickers fill when `/api/planning/qualifications/lookups` answers. The page object waits on both.
- **Date pickers open upward at 1280×720** with their month buttons off-screen, so dates are typed into the picker's "Date" box and applied.
- **Overall efficiency only saves on a time-based home centre** (LINE-30 on both envs); a cycle-based one (DYE-A) is refused with a 400 toast (TC-COQ-15, a pass on review).
- **The floating "Ask FloorOS AI" button covers the right of footer buttons** (TC-XOQ-12, a pass on review): the page object clicks them near the left edge.
- **No Activity qualifications in the current build** (dev and uat, checked 2026-11-20): the add row and the table have only Task, the Certifications roll-up is a plain count ("10", not "10· 10 task"), empty pickers read "Select…", and adding with no task says "Required". The ClickUp steps above still describe activities; the spec asserts what the screens do now and the activity cases (TC-LOQ-13, TC-COQ-07, TC-EQQ-03, TC-EQQ-04) skip while there is no Activity picker. If activities come back, TC-VOQ-04/05 and TC-EQQ-01 need the Activity column re-added.
- **uat has only one department (Sewing)** (2026-11-17): TC-XOQ-10 skips there.
- **Eventual consistency:** a new employee can take a while to appear in the Employee picker (uat, seen twice in one run, gone on rerun), and an employee's department change takes a moment to reach the Operators list (TC-XOQ-10 polls).
- **TC-XOQ-03 needs the qualification-only login**: set `PLANNING_QUALIFICATION_USER_<ENV>` / `PLANNING_QUALIFICATION_PASSWORD_<ENV>`; it skips without them.
- The tasks offered for qualifications on dev include other suites' operations (OP-xxxx, some QA-AUTO); the suite prefers the seed SEW- tasks.
