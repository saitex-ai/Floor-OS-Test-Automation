Alert timers (`/planning/master-data/alert-timers`, tile "Alert timers" under **Organisation** on `/planning/master-data`) set how non-critical planning alerts reach each person with Planning access: Real time, a Daily digest or a Weekly digest, which sections, which channels. New is `/new`, Details `/:userId`, Edit `/:userId/edit` (`:userId` is the person's account id, a UUID).

**Test data: none is created.** A timer belongs to a seeded user, has no free-text field a QA-AUTO marker could go in, and there is no delete. A real save would change a seeded user's timer for good, so the suite never lets one through: every case starts by blocking all POST / PUT requests to `/api/planning/digest-templates`, and the cases that save answer the request themselves (see "Simulated" below). The screens, lists, pickers and details are real, on each environment's own data.

## Notes for whoever picks this up next

- **Never let a write through.** `AlertTimersNetwork.guardWrites()` aborts every POST / PUT to `/api/planning/digest-templates` unless the case answers it (`answerSaveAsSaved`, `answerSaveWithError`, `sendSaveToMissingTimer`). Keep it as the first step of any new case: a timer can't be deleted or tagged, so one stray save permanently changes a seeded user's timer.
- **Simulated answers mirror the frontend's contract.** The planning service returns flat errors (`{code, message}`, e.g. `{"code":"NOT_FOUND","message":"This person has no alert timer"}`), and the form reads `code`, `existing.userId` (ALREADY_EXISTS → Edit with `?notice=added`) and `currentVersion` (VERSION_CONFLICT → banner with Reload); a 503 shows "Could not check this person's access right now. Try again."; anything else is a toast with the server's message. A nested `{error:{code}}` body is shown as a plain toast instead.
- **Records are picked, not pinned.** beforeAll reads the list (timers by cadence / Off / disabled account) and scans the Employee picker for one person per status (`ready` = has an account and email, no timer). A case without its record skips with the reason. uat (2026-11-17) has no saved timers and its picker offers only alice ("No Planning access") and one employee without an account, so most cases skip there.
- **Sections / Channels are checkboxes** — toggle and read them by role and `aria-checked`, never by clicking label text (that once produced a false "zero sections saved").
- **Sort is server-side** (`sortBy` = `username` / `group` / `cadence` / `lastSaved`, `sortDir`); Group sorts by group code, Alert timer by Real time < Daily < Weekly < Off.
- **Picker:** opening it lists the first 20 people unfiltered; typing searches from two characters (`?search=`).
- **TC-CAT-22** (400 field errors shown inline) was removed from the set on review (2026-10-05) after it showed nothing for a backend 400 `CADENCE_FIELDS_INVALID`; it is not automated.
