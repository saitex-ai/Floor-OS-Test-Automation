- **User Story:** As a Planner, I want to browse, search, filter and configure the Activities grid (Planning > Master Data > Activities) so I can find the activities the plan schedules.

- **Latest run:** dev, 2026-10-30, as `alice` (Admin); permission cases as carol (read-only) and dave (no access); 2 workers — 12 pass, 1 known bug.

Since Sprint 1, **"New activity" creates a draft** ("Creates a draft. Send it for approval from its page to publish it."). Only Activity code and Activity name block saving; the other required fields are listed on the draft's page as "Before it can be sent for approval, fill in: …". The suite never sends anything for approval. Cases that asserted Sprint 1 behaviour the app has deliberately changed say so in the last column.

**Test data:** every record this suite creates carries "QA-AUTO — Planning regression test data (pw-hybrid-framework). Safe to delete." (in its name, or a grade's Description), so it can be found and deleted from the backend. The suite never edits seed records. When a spec file finishes, its `afterAll` deletes the activity and recipe drafts it created and retires its difficulty grades (grades can't be deleted) — see `tests/regression/planning/support/cleanup.ts` and `test-data.ts`. Since the 2026-10-16 dev deploy, dev generates activity, recipe, operation, work-centre and machine codes (ACT-0001…, RCP-0001…, OP-0001…, WC-0001…, MC-0001…): each such record carries a run-unique tag in its name (a machine: in its QA-AUTO system link), the suite reads the generated code back after saving, and cleanup finds the record by that tag. Difficulty-grade codes are still typed (`QG<run><n>`).

## Notes for whoever picks this up next

- The grid is the shared Master Data grid (`MasterDataListPage`): data rows are the ones with a "Select row …" checkbox; until they render, the table shows skeleton rows and the tabs read 0 — `expectLoaded()` waits past that.
- Search and filters apply after a debounce: assert with `expect.poll` / `expectEveryRowMatches()`, never a one-off read.
- Column layout is saved per user: TC-LA-03 always resets it.
- Permission cases run as the optional `PLANNING_READONLY_*` / `PLANNING_NOACCESS_*` logins (see `.env.example`) and skip without them. As of 2026-10-09 `bob` has full Activities access, so he can't stand in for either.
