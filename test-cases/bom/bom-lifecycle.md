# BOM — Lifecycle

- **User Story:** As a BOM approver, I want to approve, complete, reopen and revise a BOM — with the right action for each revision — so downstream costing always works from a locked, auditable snapshot.
- **Test-case set:** not yet created in ClickUp.
- **Automated in:** [`tests/regression/bom/04-bom-lifecycle.spec.ts`](../../tests/regression/bom/04-bom-lifecycle.spec.ts) — 21 cases, all real `test()` blocks.
- **Page objects:** [`bom-detail.page.ts`](../../src/pages/bom/bom-detail.page.ts) / [`bom-items.page.ts`](../../src/pages/bom/bom-items.page.ts) + their locators (fixtures `bomDetailPage`, `bomItemsPage`)
- **Latest run:** uat, 2026-10-08, as `alice` — **19/21 pass**, fail: TC:20, TC:21.

Walks one disposable BOM through its real lifecycle: rev 0 Open → **Costing Approve** → complete / un-complete → **Reopen** → re-approve → **Create Revision** → rev 1 Open → **Validate & Lock**. Rev 0 is approved with "Costing Approve"; any later revision with "Validate & Lock" — both only once the BOM has at least one line. TC:20/TC:21 run on a second disposable BOM, outside the serial chain, so a failure there can't skip the rest. "Create Costing Request" is opened and cancelled, never submitted (it would raise a real request in the Costing queue).

**Test data:** every techpack and BOM this suite creates carries "QA-AUTO — BOM regression test data (pw-hybrid-framework). Safe to delete." in its Description (shown as **Remark** in the techpack and BOM lists), so it can be found and deleted from the backend later. See `tests/regression/bom/support/disposable-bom.ts`.

## Notes

- There is **no Cancel BOM** action and **no Lock/Unlock** button in the UI (the API has both). Approve / Costing Approve / complete / Create Revision show **no success toast**; Create Revision stays on the current revision and offers "Open latest".
- The revisions picker shows DRAFT for an Open revision and VALIDATED for an Approved one.
