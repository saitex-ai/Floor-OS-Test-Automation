# BOM — Lifecycle

- **User Story:** As a BOM approver, I want to approve, complete, reopen and revise a BOM — with the right action for each revision — so downstream costing always works from a locked, auditable snapshot.
- **Test-case set:** not yet created in ClickUp. Bugs filed for the failing cases: [z941aby8ec](https://app.clickup.com/t/z941aby8ec) (TC:20), [z941aby8ed](https://app.clickup.com/t/z941aby8ed) (TC:21).
- **Automated in:** [`tests/regression/bom/04-bom-lifecycle.spec.ts`](../../tests/regression/bom/04-bom-lifecycle.spec.ts) — TC:1–TC:21 (all real `test()` blocks). TC:22–TC:34 are new and not yet automated.
- **Page objects:** [`bom-detail.page.ts`](../../src/pages/bom/bom-detail.page.ts) / [`bom-items.page.ts`](../../src/pages/bom/bom-items.page.ts) + their locators (fixtures `bomDetailPage`, `bomItemsPage`)

Two other uat 2-worker runs that day failed on uat server-side errors, not on these checks: the "Add Inventory Item" search timed out in TC:20's setup (TC:21 skipped), and in another run TC:18's report export never downloaded within 30 s (TC:19 skipped). Before that: uat, 2026-10-22 (main `5f975af`, after the redesign), as `alice` — **blocked at setup**: the disposable BOM is built through the Techpack screens, whose old "TechPacks" heading is now "Dashboard", so none of the 21 cases ran. Before that: uat 2026-10-08, 19/21 (fail TC:20, TC:21).

Walks one disposable BOM through its real lifecycle: rev 0 Open → **Costing Approve** → complete / un-complete → **Reopen** → re-approve → **Create Revision** → rev 1 Open → **Validate & Lock**. Rev 0 is approved with "Costing Approve"; any later revision with "Validate & Lock" — both only once the BOM has at least one line. TC:20/TC:21 run on a second disposable BOM, outside the serial chain, so a failure there can't skip the rest. "Create Costing Request" is opened and cancelled, never submitted (it would raise a real request in the Costing queue).

**Test data:** every techpack and BOM this suite creates carries "QA-AUTO — BOM regression test data (pw-hybrid-framework). Safe to delete." in its Description (shown as **Remark** in the techpack and BOM lists), so it can be found and deleted from the backend later. See `tests/regression/bom/support/disposable-bom.ts`.

## Update 2026-10-23 — FloorOS redesign (2026-10-22)

Re-baselined from a live exploration of the redesigned UAT screens on 2026-10-23, walking a suite BOM through Costing Approve, complete / un-complete, Reopen, Create Revision and Validate & Lock. There is no ClickUp story or prototype for the redesign, so the live screens are the source. Element inventory: `qa-local/notes/modules/bom-ui-inventory-2026-10-23.md` (local exploration notes, not in the repo). All dialog texts in TC:1–TC:19 are unchanged.

- **Rewritten (behaviour changed):** TC:20 — the expected result is now the clear reason [z941aby8ec](https://app.clickup.com/t/z941aby8ec) asked for; uat currently answers 409 "This version is out of date. Please reload the latest revision." (open question). TC:21 — refused with "Rev 1 is still open - approve it before creating a new revision." (422); this was the regression check for [z941aby8ed](https://app.clickup.com/t/z941aby8ed), which hasn't reproduced since 2026-10-23; the ClickUp retest hasn't been done yet.
- **Reworded (locator change):** TC:14, TC:19 (the BOM detail page has no breadcrumb; the revision shows in the "<code> · Rev NN" heading).
- **New, not yet automated:** TC:22–TC:34 (costing-locked BOM, the back button, Refresh, Open latest, current-revision marker, revisions search, BOM Report tab, rev 0 Excel name, wash types list, Discard changes, button tooltips, revision Description).
- **2026-10-26 (dev):** Costing Approve needs every line to have a supplier. Lines without one show "(required)" in their Supplier cell and a "N rows missing Supplier" banner, and costing-approve answers 409 LIFECYCLE_BLOCKED. This is intended (the user, 2026-10-26). The suite now gives each such line the first active vendor ("Select a supplier", inactive vendors off), which saves at once. Where no line reads "(required)", that step does nothing.

## Notes

- There is **no Cancel BOM** action and **no Lock/Unlock** button in the UI (the API has both). Approve / Costing Approve / complete / Create Revision show **no success toast**; Create Revision stays on the current revision and offers "Open latest".
- The revisions picker shows DRAFT for an Open revision and VALIDATED for an Approved one.
