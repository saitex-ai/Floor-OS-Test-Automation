# BOM — Bill of Materials List

- **User Story:** As a BOM user, I want to see every BOM in one sortable, filterable list — by status, techpack code, customer or season — so I can find and open the record I need.
- **Test-case set:** not yet created in ClickUp.

Per-TC results are in the Verified columns. On 2026-10-28 (main 2b1b11a): the same. Before that: uat, 2026-10-22 (main `5f975af`, first run after the redesign), as `alice` — **12/17 pass**, fail: TC:8, TC:9, TC:10, TC:12, TC:17 (redesign locator/behaviour changes, see the update below). Before that: uat 2026-10-08, 17/17.

The list lives at `/bom`. It shares the Techpacks list's grid framework (same toolbar). Read-only: these cases never change a BOM, so they run against whatever BOMs the environment has.

**Test data:** every techpack and BOM this suite creates carries "QA-AUTO — BOM regression test data (pw-hybrid-framework). Safe to delete." in its Description (shown as **Remark** in the techpack and BOM lists), so it can be found and deleted from the backend later. See `tests/regression/bom/support/disposable-bom.ts`.

## Update 2026-10-23 — FloorOS redesign (2026-10-22)

Re-baselined from a live exploration of the redesigned UAT screens on 2026-10-23 (as `alice` and `bob`). There is no ClickUp story or prototype for the redesign, so the live screens are the source. Element inventory: `qa-local/notes/modules/bom-ui-inventory-2026-10-23.md` (local exploration notes, not in the repo).

- **Rewritten (behaviour changed):** TC:9 (Filters is now a "Filter" dialog; the rule builder sits behind Advanced Filter), TC:12 (the split buttons are now a View menu: List View / Vertical Split / Horizontal Split, with Essential / Detailed cards), TC:17 (the language moved to user menu → Preferences).
- **Reworded (locator change):** TC:8 (the BOM detail page has no breadcrumb; it is identified by its "<code> · Rev NN" heading).
- **Retired (the user's decision, 2026-10-23):** TC:10, "Toggle cell filters". The list has no per-column filters any more (they remain on the BOM items table, items TC:33-34). Narrowing the grid is covered by the Filter dialog (TC:9, TC:18-20). The number is not reused.
- **New, not yet automated:** TC:18–TC:34 (Filter dialog count / multi-select / apply-clear / date range, column chooser, sorting, pager, search scope, empty state, View persistence, Essential / Detailed (TC:31, retired 2026-10-30), the "BOM" back control, nav collapse, the ⌘K palette).
- **2026-10-26:** TC:4 leaves out legacy BOMs with the old 7-digit sequence when it checks Approved Dates (7 such Approved BOMs on dev have none). The user's call: legacy data, not a Fail.

## Update 2026-10-30 — dev and uat deploy

- **TC:1-4, TC:16, TC:17:** All / Open / Approved are tabs now (`role="tab"`, the selected one `aria-selected`), not `aria-pressed` buttons. Steps and expected results are unchanged; the suite's locators follow.
- **TC:12:** Vertical Split no longer shows an Essential / Detailed switch, on dev or uat (checked live on 2026-10-30). The rest of TC:12 is unchanged. The check for the switch is removed from the test.
- **Retired (the user's decision, 2026-10-30):** TC:31, "Essential and Detailed card modes". The switch is gone from Vertical Split on dev and uat. The number is not reused.

## Notes

- BOM has only **All / Open / Approved** tabs (no Draft, no Cancelled — a Cancelled BOM is only findable through the Status column filter, and the UI has no Cancel action at all).
- The tab badges load separately from the grid rows; `BomListPage.waitForTabCounts()` waits for them before any count is read.
- Rewritten 2026-10-08 against the UAT build (`build/uat`, 2026-10-01). Supersedes the 2026-09-25 doc-only catalogue.
