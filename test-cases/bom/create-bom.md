# BOM — Create BOM

- **User Story:** As a planner, I want to create a BOM from an approved techpack, seeded with its customer, style, fabric and product details, so I can start adding material lines.
- **Test-case set:** not yet created in ClickUp.
- **Automated in:** [`tests/regression/bom/02-create-bom.spec.ts`](../../tests/regression/bom/02-create-bom.spec.ts) — 10 cases, all real `test()` blocks.
- **Page objects:** [`bom-list.page.ts`](../../src/pages/bom/bom-list.page.ts) + [`bom-list.locators.ts`](../../src/locators/bom/bom-list.locators.ts) (fixture `bomListPage`), [`bom-detail.page.ts`](../../src/pages/bom/bom-detail.page.ts)
- **Latest run:** uat, 2026-10-08, as `alice` — **10/10 pass**.

"New BOM" opens the **Create BOM techpack** dialog; its techpack picker (a table — click a row to pick) only offers **Approved** techpacks that have **no BOM yet**. The suite builds its own Approved techpack first (Classic form → approve on its canvas) and creates exactly one BOM for it. A Classic techpack has no AI-extracted BOM lines, so approving it doesn't trigger an auto-BOM — it lands in the picker instead.

**Test data:** every techpack and BOM this suite creates carries "QA-AUTO — BOM regression test data (pw-hybrid-framework). Safe to delete." in its Description (shown as **Remark** in the techpack and BOM lists), so it can be found and deleted from the backend later. See `tests/regression/bom/support/disposable-bom.ts`.

## Notes

- The create request only ever sends `{ techpackCode }` — every header field is server-derived from the techpack.
- The picker's footer renders before its table; `BomListPage.expectTechpackPickerLoaded()` waits for the table's header row too.
- Not automated (no UI path): the server-only rejections (`TECHPACK_NOT_APPROVED`, `BEFORE_BOM_EFFECTIVE_DATE`, `BOM_ALREADY_EXISTS` race) — the picker never offers those techpacks.
